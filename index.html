Reactor

Play energizes the confining magnetic field (real reference cost: ITER's 51 GJ magnet system, charged once per shot) and starts accelerating/heating the fuel ions — the field, current, and heating powers ramp up over about 1.4s (see "The shot" below), visibly driving the new diagnostics dashboard up with them. Reset de-energizes the field (ramping back down) and ends the shot — fuel, clock, and the activation cost all return to zero, so the next Play pays it again. Deplete burns fuel down following n(t) = n₀/(1 + n₀⟨σv⟩t) — real depletion timescales are tens of seconds to minutes at 1×, so try a higher speed to see it happen quickly. Sustained refuels exactly as fast as fuel burns, holding density constant. The plasma visibly fades as fuel depletes, and its pulsing glow tracks instantaneous fusion power — both above and in the 3D view below, all tied to the same numbers.

A tokamak's magnetically confined plasma settles into a steady axisymmetric state described by the Grad–Shafranov equation. This page solves it directly, the way eigendrum solves the clamped-membrane eigenvalue problem for a drum shape — a real PDE, solved live with finite elements, not a canned animation.

The equation

∫∫ (1/R) ∇ψ·∇v  dR dZ  =  ∫∫ ( R p'(ψ) + FF'(ψ)/R ) v  dR dZ,      ψ = 0 on the boundary

ψ is the poloidal flux; its contours are the nested flux surfaces the plasma actually organizes itself along — the direct analog of eigendrum's nodal lines. p'(ψ) and FF'(ψ) are the pressure and toroidal-field profile functions that define a given steady state.

Fixed boundary, on purpose

The plasma boundary shape (elongation, triangularity) is imposed directly here, not computed self-consistently from external coil currents the way a real free-boundary equilibrium code (EFIT, CHEASE) would. That's the direct equivalent of eigendrum's clamped ψ = 0 edge condition, and it's the standard simplification used by fixed-boundary equilibrium solvers.

Custom shapes, by equation

Besides the three fixed presets, the boundary can also be typed directly as a polar equation — the direct analog of eigendrum's "from an equation" panel. The boundary is R(θ) = R₀ + r(θ)cos θ, Z(θ) = r(θ)sin θ for a user-supplied r(θ) (fixed center R₀ = 3.0, matching the circular preset). This needed no new mesher: the O-grid mesh already had a generic path, buildOGridMeshFromBoundary, that linearly interpolates any star-shaped boundary curve in from the center — until now it was only used internally to validate the solver against Solov'ev's own zero-flux contour (see Validation, above). A hand-written expression parser (no eval, matching the "no dependencies" rule below) compiles r(θ) client-side; it's rejected before meshing if it isn't finite and positive everywhere, which would otherwise self-intersect the mesh. Free-hand drawing (eigendrum's other input mode) is deliberately not offered here — a hand-drawn curve is routinely not star-shaped, which would need real unstructured meshing with point-in-polygon repair, for comparatively little physical payoff (a doodle isn't a meaningful plasma boundary the way it's a meaningful drum).

The 3D view

Tokamak equilibria are axisymmetric by construction — nothing depends on the toroidal angle φ — so the 3D torus is literally the 2D (R,Z) solve above, swept through φ ∈ [0, 2π): X = R cos φ, Y = Z, Z = R sin φ. The nested surfaces shown are the O-grid mesh's own ρ-rings (at ρ = 0.15, 0.4, 0.7, 1.0), revolved this way and colored with the same edge-to-core colormap as the 2D plot — the same technique the 3D stellarator viewer uses for its (non-axisymmetric, precomputed) surfaces, just built from this page's own live solve instead of a DESC file. The magnet coils and control cabinets are schematic: sized from the current shape's own bounding box plus a fixed margin, not a specific reactor's engineering design. While Play is running, the core surface's brightness and a point light at the magnetic axis pulse with the same powerLevel/pulse phase already driving the 2D glow (see Live fuel burn, below) — same validated number, two views.

Why no eigensolver

Unlike the drum problem, this isn't an eigenvalue problem — it's a sequence of linear solves. p'(ψ) and FF'(ψ) depend on the unknown ψ itself, so the equation is nonlinear; it's solved by Picard (fixed-point) iteration: guess ψ, normalize it against the current magnetic-axis value, evaluate the profile functions, solve the resulting linear system, repeat until it stops changing. The stiffness matrix depends only on mesh geometry (not on ψ), so it's built once and reused every iteration — only the right-hand side changes — which is why a plain Jacobi-preconditioned conjugate gradient solver is enough, no direct factorization or eigensolver required.

Validation

For the special case where p' and FF' are both constant, a closed-form solution exists — the classical Solov'ev equilibrium (Solov'ev, 1968; see also Freidberg, Ideal Magnetohydrodynamics). This is the same role eigendrum's Bessel-function validation plays for the circular drum. Meshing the solver's mesh against that solution's own zero-flux contour and refining resolution gives clean second-order convergence: 

nRho   nNodes   L2 error
 8      385     6.3e-3
16     1537     1.8e-3   (3.6× reduction)
32     6145     4.8e-4   (3.6× reduction)
64    24577     1.3e-4   (3.7× reduction)

This validation is restricted to up-down symmetric (zero-triangularity) boundaries, which is what the closed form covers exactly. The shaped presets above (ITER-like, spherical tokamak) use the same validated solver and assembly code, just without an independent closed-form check of their own.

Units

Profile amplitudes (p₀, F₀ per steady-state preset) are solver-internal arbitrary units, chosen to make each preset's qualitative behavior clearly visible — not calibrated to real pressures or currents in pascals or amperes.

Live fuel burn

Press Play to run a real burn calculation on top of the solved equilibrium: the standard 0D power-balance model used for reactor scoping (the same category of calculation behind the Lawson criterion), not a scripted animation. Plasma volume is computed from the actual solved mesh (Pappus's theorem per triangle, treating R,Z as meters). Play doesn't just start a clock — it represents energizing the confining magnetic field, which has a real energy cost: the first Play of a "shot" charges a one-time activation energy (ITER's real 51 GJ magnet-system figure), tracked against cumulative electric output as a real input/output balance on the energy-vs-time chart below (see "Where the energy goes" for how the breakeven point on it is found), not just a comparison line. Pausing doesn't re-charge it; only Reset — de-energizing the field and ending the shot — does, so the next Play pays it again. Deplete mode has no refueling — dn/dt = -<σv>n² — which has an exact closed-form solution n(t) = n₀/(1+n₀<σv>t), so power and cumulative energy are evaluated directly from elapsed time with no per-frame integration to accumulate error. Sustained mode refuels exactly as fast as fuel burns, holding density (and power) constant — real reactors need continuous pellet injection for exactly this reason, since natural burn-down timescales at these densities are tens of seconds to minutes at 1×, not hours (try a higher speed multiplier to see a full burn-down in a few seconds).

The plasma's fill fades toward the background as fuel depletes (both here and in the 3D view below) — a direct visual read on n(t)/n₀, so a spent plasma no longer looks identical to a fresh one. This is a presentation cue layered on top of the already-solved static equilibrium, not a re-solved Grad-Shafranov shape — the flux-surface contours and boundary stay exactly as solved; only the pressure fill's opacity changes. The 3D magnet coils likewise dim when the field is off (Reset, or before the first Play) and take on a blue energized tint while Play is active — tied to the same burnPlaying state as the activation-energy charge above, not a simulated magnet ramp time.

Temperature and initial fuel density are illustrative, reactor-ballpark operating points assigned per steady-state preset (roughly 6–15 keV, ~0.6–1.1×10²⁰ m⁻³ — in ITER's target range), not derived from the solver's arbitrary-unit pressure profile amplitudes, and the same for every fuel (see below); the equilibrium shape itself stays the already-solved static one rather than being re-solved as fuel depletes. The net-energy figure nets electric output against the one-time magnet-activation cost only — it's still not a true Q-factor, since continuous heating power and energy-confinement-time losses (which a real reactor also has to pay for, continuously, not just once at startup) aren't modeled here; that would need transport/confinement-time physics this page doesn't attempt.

Choosing a fuel

The Fuel selector switches which reaction <σv>(T) and energy release Q feed the burn model above — same 0D power balance, different nuclear physics. All three use the Bosch & Hale (1992) R-matrix parametrization already cited for D-T, extended to D-D's two channels and D-³He: 

D-T:   D + T   → ⁴He(3.5 MeV) + n(14.1 MeV)          Q = 17.6 MeV
D-D:   D + D   → T(1.0 MeV) + p(3.0 MeV)             Q = 4.03 MeV   (~50%)
       D + D   → ³He(0.8 MeV) + n(2.4 MeV)            Q = 3.27 MeV   (~50%)
D-³He: D + ³He → ⁴He(3.6 MeV) + p(14.7 MeV)           Q = 18.3 MeV   (aneutronic)

D-D is a self-reaction (both reactants are deuterium), which changes the bookkeeping but not the burn-down formula above: the reaction-rate pair-counting factor (½, since D-D collisions are counted once per pair) and the fact that each reaction consumes two D ions exactly cancel, so dn/dt = -<σv>n² holds for D-D too, with <σv> summed over both channels — the same closed form, not a coincidence, and checked by re-deriving it before implementing (see src/fusion/burn.js). Power still needs the two D-D channels' different Q weighted separately, since they release different energy and one is neutron-heavy and the other isn't.

All four reaction channels' coefficients were checked to within 0.4% against an independently reproduced copy of the Bosch-Hale paper's own reference table before being used here (tools/validate_reactivity.mjs) — see References. Temperature and density stay fixed across fuel choice (above), so switching to D-³He at these D-T-range temperatures shows a genuinely, correctly tiny reaction rate: D-³He has a higher Coulomb barrier (helium's +2 charge vs. deuterium/tritium's +1) and its reactivity only becomes comparable to D-T's at much higher temperature — real D-³He reactor concepts are generally envisioned at 50–100+ keV, not the 6–15 keV used here. That's not a bug; it's the actual reason D-T is the near-term fusion fuel of choice.

Where the energy goes

Raw fusion power isn't electricity. The Energy capture selector applies a simple two-stage conversion on top of the already-computed power/energy above, split by how much of each fuel's output is carried by neutrons vs. charged particles (from the table above — e.g. D-T is ~80% neutron, D-³He's primary channel is ~0%): 

P_electric = ( n_frac × captures_n × blanket_multiplier  +  c_frac × captures_c ) × η_thermal × P_fusion

Blanket + steam turbine captures both: a Li/Be breeder blanket multiplies neutron energy (~1.15×, typical cited range 1.1–1.3× for conceptual designs — the (n,2n) reactions that also breed tritium release extra energy), then everything drives a steam (Rankine) cycle at ~34% thermal-to-electric efficiency (typical cited range 30–40%). Direct conversion electrostatically decelerates charged fusion products directly into current at a higher ~60% efficiency (theoretical range up to 60–90%, experimental only, never deployed at reactor scale) — but captures none of the neutron energy at all, which is why it does badly on D-T (mostly neutrons) and well on D-³He (no neutrons in the primary channel). Try pairing them: D-T + blanket/steam is the closest to a real near-term reactor; D-³He + direct conversion is the "no neutrons anywhere" aspirational case; the other two pairings show why picking the wrong capture technology for a fuel leaves most of the power on the table. These multiplier/efficiency numbers are illustrative literature ballparks for conceptual designs, the same epistemic status as the temperature/density operating points above — not a specific engineering design, and not independently closed-form-checked the way the solver or the reactivities are.

The energy-vs-time chart plots this electric-output curve (not raw fusion energy) against a flat input line at whatever's actually been charged so far — 0 before the first Play, the magnet's activation energy afterward, per the "Live fuel burn" section above. Since the capture conversion is a fixed multiplier (it doesn't depend on t), the breakeven point where output crosses input is found from the same closed-form inverse already used for the raw-energy version, just at a rescaled target — the marked dot is exactly where cumulative electric output would pay back the one-time activation cost, at the current fuel/capture/timeframe settings.

Plasma diagnostics

Near the 2D slice and in the "Plasma parameters" panel below, a set of real JET/DIII-D- style operational numbers are shown — Bt, Ip, an H-mode/L-mode badge, β_N, q_95, W_th, H98, τ_E, l_i. These sit on top of the arbitrary-unit solve above via a new Operating point preset (real Tesla/MA/MW inputs — Bt, Ip, and auxiliary heating powers — which can't be derived from the solver's own profile amplitudes, so they're new inputs, same epistemic tier as the burn model's existing temperature/density operating points). From there, most of what's shown is genuinely computed, not hand-set:

  • l_i (internal inductance) = ⟨B_θ²⟩volume / B_θ²(edge), computed directly from the already-solved ψ field: B_θ ∝ |∇ψ|/R, with a constant gradient per triangle from the same P1 shape-function coefficients assembleStiffness already uses. Since B_θ is proportional to ∇ψ everywhere, this ratio is invariant to ψ's arbitrary overall scale — genuinely computable from the arbitrary-unit solve, no calibration needed. Checked against the textbook l_i=0.5 result for a flat current-density profile (tools/validate_flux_diagnostics.mjs), converging cleanly as mesh resolution increases.
  • W_th (thermal stored energy) = 3·n_e·T·V, the kinetic definition (T_e=T_i=T, n_e≈n_i, the same single-temperature assumption the burn model's operating points already make), using the already-computed real plasma volume (Pappus's theorem, see "Live fuel burn") and the operating point's real n_e/T — real, no new calibration.
  • β_N follows from that same W_th: volume-averaged pressure p̄ = (2/3)(W_th/V), β = p̄/(B_t²/2μ₀), β_N = β[%]·a[m]·B_t[T]/I_p[MA] — real, using the new Bt/Ip inputs and the shape's own real minor radius.
  • q_95 uses Ampère's law to turn the new Ip input into a real poloidal field at the edge (B_p(a) = μ₀I_p/2πa), combined with the standard large-aspect-ratio, elongation-corrected safety factor q ≈ (2πa²B_t)/(μ₀R₀I_p) · (1+κ²)/2 (Wesson, Tokamaks). This is an approximation, not the exact flux-surface- averaged line integral at the 95%-flux surface — see "Not in this first pass".
  • τ_E and H98: τ_E,actual = W_th/P_loss (the literal definition of energy confinement time, using the power balance below) is compared against the IPB98(y,2) ELMy H-mode scaling law — τ_E = 0.0562 · I_p^0.93 · B_t^0.15 · n̄_e^0.41 · P_loss^-0.69 · R₀^1.97 · κ^0.78 · ε^0.58 · M^0.19 (ITER Physics Basis / ITPA database) — and H98 = τ_E,actual / τ_E,IPB98 is a genuinely computed diagnostic ratio, exactly how it's reported for real shots, not a dial the preset sets directly.
  • H-mode / L-mode badge: compares the auxiliary heating power (P_NBI+P_ECH+P_ICH) against the Martin08 L-H transition threshold scaling, P_LH[MW] = 0.0488 · n̄_e[10²⁰m⁻³]^0.717 · B_t^0.803 · S[m²]^0.941 · (2/A_eff), using the plasma's real surface area (Pappus's theorem on the boundary polyline, the same technique as the volume calculation, one level down).
  • P_alpha reuses the burn model's own already-computed split — chargedFrac × P_fusion(t) — from "Choosing a fuel", not a new estimate.

All the formulas above marked real were verified this session against independently re-transcribed references or hand-worked arithmetic before shipping (tools/validate_diagnostics.mjs, tools/validate_flux_diagnostics.mjs) — see Verification-style checks throughout this panel for the project's general discipline on that.

Power balance

The "Power and fusion" panel is a standard 0D power balance: P_heat = P_OH + P_NBI + P_ECH + P_ICH + P_alpha (the auxiliary-heating inputs from the Operating point preset, plus the reused P_alpha above); P_loss = P_heat − P_rad − dW/dt; P_in = P_heat; P_out = P_rad + P_loss + dW/dt. P_out sums to exactly P_in by construction here — a real balance equation, not fitted to match any particular example shot's numbers (which need not balance exactly). dW/dt is a genuine transient: a finite difference of W_th, nonzero during the magnet/current ramp (see "The shot" below) and ~0 at flat-top. P_rad is the one illustrative input feeding this otherwise-real balance — this session couldn't verify a trustworthy Bremsstrahlung coefficient/unit convention from source, so it uses an n_e²√T-shaped functional form calibrated to a representative point rather than a checked formula, the same epistemic tier as the divertor numbers below.

Divertor illustrative

λ_q, f_det, q_i, and T_s are not independently verified this session — real SOL/divertor transport (detachment physics, target thermal response) is well beyond this page's 0D scope. λ_q cites the functional form of the Eich et al. (2013 Nucl. Fusion) regression-#14 scaling (λ_q[mm] = 0.63·B_p,MP[T]−1.19, using the Ampère's-law-derived edge field above) without independently re-deriving or checking its coefficient against source data. q_i spreads the real P_loss over a wetted area estimate (with an illustrative flux-expansion/spreading factor — real divertor targets see a much larger footprint than the bare midplane mapping, or this would overshoot real heat fluxes by ~100×). f_det and T_s are simple monotonic functions in the qualitatively correct direction, each calibrated to a single representative reference point rather than derived. Treat this section the way the energy-capture multipliers are already treated elsewhere on this page: illustrative, literature-flavored, not load-bearing physics.

The shot

Press Play and the confining field doesn't just switch on: Ip, Bt, and the auxiliary heating powers ramp up over about 1.4 seconds (real time, independent of the fuel-burn clock's speed multiplier — a magnet/current ramp is a hardware timescale, not a simulated-time one), the 3D coils brighten continuously with it, and every diagnostic above — β_N, q_95, τ_E, H98, the power balance, the H-mode gate — recomputes each frame from these ramping values, so the whole dashboard visibly rises together rather than snapping on. Pause or Reset ramps back down over about 1.1 seconds the same way, independently of the fuel-burn clock (which still freezes/zeros exactly as before — see "Live fuel burn"). At flat-top, a small deterministic texture (a couple of off-frequency sine waves, the same idiom as the 2D glow's pulse) is layered onto Ip, W_th, and a stylized D-α trace with periodic ELM-like spikes, so the "Shot trace" strip chart settles around a fixed value rather than sitting dead flat — an illustrative shot-trace texture, not a turbulence simulation. That texture is deliberately kept out of dW/dt's finite difference (computed from a separate, unjittered trajectory), so the power balance above stays a real ~0 at flat-top instead of amplifying cosmetic noise into a spurious transient. The existing fusion-power/energy stat tiles above (from "Live fuel burn") keep representing that already-validated closed form directly, unramped — the ramp modulates the new real-unit diagnostics layered on top, not the underlying 0D burn physics. The "Shot trace" chart renders in real time frame-by-frame (unlike the closed-form energy-vs-time chart above it, which can sample any horizon instantly), so it's most legible at lower speed multipliers.

Not in this first pass

The exact flux-surface-averaged line integral for q(ψ) — and full safety-factor profiles / rational-surface resonances more generally, the direct fusion analog of "striking a resonant mode" — still need contour extraction at arbitrary ψ levels and aren't implemented here; q_95 above uses a documented large-aspect-ratio approximation instead (see "Plasma diagnostics"). Stellarators are inherently three-dimensional and aren't handled by this page at all; they're a separate viewer built from equilibria precomputed offline (VMEC/DESC) rather than solved live in-browser — see the 3D stellarator viewer. The burn model doesn't re-solve the equilibrium as pressure drops and doesn't evolve temperature — T/n stay the fixed operating-point values from "Live fuel burn" throughout a shot, even though the new power balance above now does track input heating power and energy confinement time as real quantities. D-³He's real side reactions (it's not perfectly aneutronic in practice — some D-D branching still happens in a D-³He plasma) aren't modeled; only the primary D+³He channel is.
